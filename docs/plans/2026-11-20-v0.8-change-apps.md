# kwhy v0.8 (`kwhy change` for several apps: `.kwhy.yaml`, Argo CD, Flux) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** one `kwhy change` run covers every app in a repo (backlog C3, C4): from a `.kwhy.yaml` list, or discovered from Argo CD `Application` and Flux `HelmRelease` objects in the repo, with each app's values, release name and namespace.

**Architecture:** `change.Target` is a `Source` plus release and namespace. `LoadConfig` reads `.kwhy.yaml`; `Discover` reads Argo CD and Flux objects from the working tree and returns targets plus warnings for what it skips. The CLI renders and diffs each target and merges the impacts. `Render` treats an in-repo path missing at a ref as an empty render, so an app added in the PR is `create` and a removed one `delete`.

**Spec:** `docs/specs/02-change.md`.

## Global Constraints

- Discovery never guesses: a source from another repo, a chart from a Helm repository, Flux `valuesFrom` and Kustomize are skipped with a warning that names the object and why.
- Definitions are read from the working tree (in CI, the PR's merge commit); each target's chart and value files are read at each ref as today.
- Inline values (Argo `helm.values`/`valuesObject`, Flux `spec.values`) go through a temp values file, removed afterwards.
- Gate per task, commits per task, as before.

## Notes from executing (2026-11-20)

- All targets' documents go through one `Diff` instead of one diff per target: simpler, and a ConfigMap in one app
  consumed by another is still seen.
- `--release`/`-n` with `--config` or `--apps` is a usage error (they come from the file or the apps); a `--chart`
  or `--manifests` path missing from the working tree is a usage error, so a typo can't render as "nothing".
- The remote check compares normalised URLs (scheme, user, `.git`, ssh `host:path` form). Without an `origin`
  remote every `repoURL` is accepted.
