# kwhy v0.6 (`kwhy pod` completeness) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** close the `pod` rows of `docs/plans/2026-11-20-backlog.md` that a user hits often: a workload whose controller can't create pods or whose rollout is stuck (P1), a failed Job (P2), pods stuck terminating (P3), `ds/` targets (P4), autoscaler events (P6), the cluster's version for `--chart` (P9), and a preemption hint (P5).

**Architecture:** `pod/` gains `Controller`: for a workload ref it reads the controller's conditions and Warning events (and a Deployment's ReplicaSets') and returns `Problem`s of three new kinds (`create`, `rollout`, `job`). The CLI adds them to whatever the pod diagnosis or the scheduling matrix says; when a workload has no pods and its controller has problems, those are the answer and the template check is skipped. Scheduling gains `autoscaler` problems from the pod's events and a preemption hint from a second evaluation without lower-priority pods.

**Spec:** `docs/specs/03-pod.md`, `docs/plans/2026-11-20-backlog.md`.

## Global Constraints

As v0.5: read-only (`get`/`list` on workloads, replicasets, events), kubelet's and the controllers' own words, no fixes suggested, `kwhy.pod/v1` additive only, gate per task, commits per task.

## Tasks

### Task 1: Controller problems (P1, P2, P4)
- [ ] `Target` accepts `ds/` (DaemonSet: selector and template like the others).
- [ ] `Controller(ctx, c, ns, ref) ([]Problem, error)`: Deployment `Progressing=False/ProgressDeadlineExceeded` → `rollout`; its ReplicaSets' `ReplicaFailure=True` or `FailedCreate` events → `create`; StatefulSet, DaemonSet and Job `FailedCreate` events → `create`; Job `Failed=True` → `job` with the condition's reason and message. A pod ref has none.
- [ ] CLI: workload refs get controller problems added to the result; with no pods and controller problems, the template check is skipped. A healthy workload with controller problems (a stuck rollout behind ready old pods) shows them instead of "all N pods ready".
- [ ] Tests with fake clients for each source; title for "no pods" (`ns/deploy/x has no pods`).

### Task 2: Pods stuck terminating (P3)
- [ ] `Diagnose`: a pod deleting for longer than its grace period plus a minute → `terminating` with finalizers and how long; `Target` may pick such a pod when nothing else is wrong.

### Task 3: Autoscaler events (P6) and the cluster's version for `--chart` (P9)
- [ ] Pending pod: Warning/Normal events `TriggeredScaleUp`, `NotTriggerScaleUp` (Cluster Autoscaler) and `Nominated` (Karpenter) → `autoscaler` problems shown with the matrix.
- [ ] `--chart` on a pod on a node renders with the API server's version.

### Task 4: Preemption hint (P5)
- [ ] For a pod with priority above some running pods, evaluate again with every lower-priority pod removed; nodes that fit then are reported as "would fit on N nodes if lower-priority pods were preempted", with the caveat that the scheduler also weighs PDBs and picks the fewest victims.

### Task 5: Kind fixtures and docs
- [ ] Kind: a Deployment blocked by a `ResourceQuota` (create), a Job with `backoffLimit: 0` (job), a pod with a finalizer deleted (terminating), a high-priority pod that fits only by preemption (hint).
- [ ] README, spec, backlog rows closed.
