# kwhy v0.2 (`kwhy value kustomize`, release binaries) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `kwhy value` answers "which line sets this field?" for local Kustomize overlays as well as for Helm charts, through two subcommands (`value chart`, `value kustomize`), and kwhy ships as release binaries.

**Architecture:** `render/` gains a Kustomize overlay: an in-memory copy of the tree the stack uses, a `krusty` build into the same `[]render.Doc` Helm renders produce, the stack's removable entries, and a build with one entry removed. `value/` gains leave-one-out attribution (parallel builds, document identity, name-keyed list comparison, "added by") and answers in the existing `Answer`/`kwhy.value/v1` shape, with line lookup per entry type. `cmd/kwhy` splits `value` into `value chart` and `value kustomize`. The algorithm is the validated spike in `docs/spikes/kustomize/main.go` (read its README); port its logic, don't import it.

**Tech Stack:** Go 1.27.1, `sigs.k8s.io/kustomize/api` v0.21.1 and `sigs.k8s.io/kustomize/kyaml` v0.21.2 (already in the module graph through Helm; become direct), `go.yaml.in/yaml/v3`, `github.com/spf13/cobra` v1.10.2, `golang.org/x/sync/errgroup`, goreleaser (CI only, not a Go dependency).

**Spec:** `docs/specs/01-value.md` (sections "Kustomize (v0.2)" and "Output"), `docs/specs/00-overview.md`, and `docs/spikes/kustomize/README.md` (the rules). Read all three.

## Global Constraints

- Read-only: kwhy never writes the user's files. Overlays are copied into memory; entries are removed only in that copy.
- Offline: no network. Remote bases, `helmCharts:` and plugins stop with an error (see Task 2).
- Never name a wrong line: when a line or an override can't be certain, leave it out.
- JSON stays `"schema": "kwhy.value/v1"` with the same fields; Kustomize answers use the existing kinds only.
- New direct dependencies: `sigs.k8s.io/kustomize/api`, `sigs.k8s.io/kustomize/kyaml` (reason: Kustomize's own build, not a reimplementation). Keep the versions the module graph already has.
- Follow the `go-guidelines` skill. Gate for every task: `gofmt -l .` prints nothing, `go vet ./...` and `go test -race ./...` pass.
- Commits: Conventional Commits, subject under 50 chars, only once the user approved executing this plan. Pushing tags or creating releases needs the user's go-ahead.

## Review Focus

1. **Overlay paths as typed** (`overlays/prod/`, `../repo/overlays/prod`, an absolute path): every printed file is relative to what the user typed, like Helm's `-f` files. Test in Task 5 (`TestRunKustomizePathsAsGiven`).
2. **A directory without a kustomization file**, or one whose baseline build fails: exit 1, `build overlay: …` with Kustomize's message, no panic, no attribution attempt. Test in Task 2 (`TestLoadOverlayErrors`) and Task 5.
3. **An entry whose removal fails the build** (a `behavior: merge` generator whose base generator then has nothing to merge into): no attribution from that entry, the answer still comes out. Test in Task 3 (`TestTraceOverlaySkipsFailingRemovals`).
4. **The same kind several times in one file, plus a `namePrefix`**: each document keeps its identity across leave-one-out builds. Test in Task 3 (`TestTraceOverlayMultiDocPrefix`).
5. **A list item inserted by a patch** (an env var added in front of others): later items are not attributed to that patch. Test in Task 3 (`TestTraceOverlayListInsert`).

  ```go
  package render
  type Overlay struct { /* unexported: dir as given, in-memory fs, stack */ }
  func LoadOverlay(dir string) (*Overlay, error)
  func (o *Overlay) Build() ([]Doc, error)               // Doc.Source: the resource file, relative to what the user typed
  func (o *Overlay) Entries() []Entry                    // every removable entry of every kustomization in the stack
  func (o *Overlay) BuildWithout(e Entry) ([]Doc, error) // safe for concurrent use
  func (o *Overlay) File(path string) []byte             // a file as on disk (Entry.File, Entry.Patch, Doc.Source)

      Inline string // inline patch text, if any

      Values map[string]int // line of each sub-key: count, newTag, digest, newName; scalar value line under ""

  ```

### Task 3: Leave-one-out attribution

**Files:**
- Create: `value/kustomize.go`, `value/kustomize_test.go`, small fixtures under `testdata/kustomize/` for the Review Focus cases (`multidoc/`, `listinsert/`, `failremoval/`)

**Interfaces:**
- Consumes: Task 2's `Overlay`, `Entry`, `Doc`.
- Produces:
  ```go
  package value
  type OverlayIndex struct {
      Docs    []render.Doc
      Fields  map[Field]any        // baseline, canonical paths (index form, as Flatten)
      Moved   map[Field][]int      // Entry indexes whose removal changes the field (last writers)
      AddedBy map[int]int          // doc index → Entry index whose removal drops the whole doc
      Entries []render.Entry
  }
  func TraceOverlay(ctx context.Context, o *render.Overlay) (*OverlayIndex, error)
  ```
  Builds run in parallel (`errgroup`, `GOMAXPROCS` at a time), like `Trace`. Documents match across builds by `docKeys` (kind + `Source` + position; already in `explain.go`). Fields compare with named list items keyed by `name` (`env[name=PORT]`), then map back to canonical index paths of the baseline for `Fields`/`Moved`. A doc missing from a build goes to `AddedBy`, not `Moved`. A removal whose build fails is skipped. When a `components[i]` entry and an entry inside that component both moved a field, keep only the inner one.

### Task 4: Kustomize answers and line lookup

**Files:**
- Modify: `value/kustomize.go`, `value/kustomize_test.go`, `value/report.go` (resource leaf label), `value/testdata/golden/kustomize.{txt,md,json}`

**Interfaces:**
- Consumes: `OverlayIndex`, `render.Overlay.File`.
- Produces:
  ```go
  func ExplainOverlay(idx *OverlayIndex, o *render.Overlay, f Field) (Answer, error)
  func ExplainOverlayAll(idx *OverlayIndex, o *render.Overlay, doc int) ([]Answer, error) // sorted by path
  ```
  Answer shape (`kwhy.value/v1`, existing kinds only); `Answer.Template` holds the resource file:
  - No entry moved it: `direct`, one leaf `{Path: {"resource"}, Chain: [resource file:line]}`.
  - One entry moved it: `direct`, leaf `{Path: entry.Path, Chain: [entry line, then overridden patch lines, then resource file:line if the resource sets the field]}`.
  - `namePrefix`/`nameSuffix`/`images` moved it: `composed`, leaves = that entry + the resource leaf.
  - A generator or generator literal moved a `name` field (`.metadata.name`, `…Ref.name`): `hashed`, leaves = those entries.
  - Several entries otherwise: `composed`, one leaf each.
  - Doc in `AddedBy`: `structural`, leaves = the adding entry + the resource leaf.
  Line lookup, ported from the spike's `lineFor`, `patchLine`, `opLine`, `inlineLine`, `findLineDoc`, `resourceLine`: strategic-merge patch files by path within documents of the resource's kind, never `apiVersion`/`kind`/`metadata.name`/`metadata.namespace`; JSON6902 ops (file or inline) by the op whose path is the field or a parent, then inside its `value`; `replicas` → `count`, `images` → `newTag`/`digest`/`newName`; scalar entries → their value line; generated data → the `KEY=` literal; resource files by kind + position. Overridden lines: other patch entries whose `Target` can match the doc and whose file sets the path. **Leave out** any overridden line found through a JSON6902 op whose path addresses a list item by index. A line that can't be found is `0` and printed as the file alone.
