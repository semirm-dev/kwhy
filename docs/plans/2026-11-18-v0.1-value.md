# kwhy v0.1 (`kwhy value`, Helm, read-only) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship `kwhy value`: point at a field of a rendered Helm chart and get the values file and line that set it, the override chain, and the kind of answer.

**Architecture:** `render/` wraps Helm v4 in-process (load, coalesce, render to docs with their `# Source`). `value/` owns positions of values leaves (`yaml.Node` merge replay), field paths, the marker tracer, the per-field explainer with a perturbation fallback, and the three output formats. `cmd/kwhy` only parses flags and wires these together. The algorithm is the validated spike in `docs/spikes/value/main.go`. Port its logic; don't copy its shelling out to `helm`.

**Tech Stack:** Go 1.27.1, `helm.sh/helm/v4` v4.3.2, `go.yaml.in/yaml/v3`, `github.com/spf13/cobra` v1.10.2 (CLI only, already in Helm's dependency tree), stdlib `testing`.

**Spec:** `docs/specs/01-value.md` (feature) and `docs/specs/00-overview.md` (shared decisions). Read both.

## Global Constraints

- Module `github.com/semirm-dev/kwhy`; `go 1.27.1`; license Apache-2.0 (LICENSE file, SPDX header not required).
- Helm v4 only (`helm.sh/helm/v4`). Never exec `helm` or `kubectl` from product code.
- Direct dependencies allowed: `helm.sh/helm/v4`, `go.yaml.in/yaml/v3`, `github.com/spf13/cobra` (only in `cmd/kwhy`; feature packages never import it). Anything else needs a written reason in the PR.
- Offline: no cluster access. `lookup` returns empty, as with `helm template`.
- Markers: strings `zq<id>qz`; numbers `900000+id`, which **must stay below 1e6** (Helm prints floats ≥1e6 as `1e+06`). Mark only truthy strings and numbers; never `""`, `0`, bools or nulls.
- Tracing chunk size 40 leaves per render; bisect a chunk on render error or document-shape change.
- JSON output carries `"schema": "kwhy.value/v1"`.
- Answer kinds (exact strings): `direct`, `composed`, `derived`, `encoded`, `hashed`, `chart`, `structural`, `random`.
- Follow the `go-guidelines` skill (feature packages, consumer-owned interfaces, handle-or-return errors, lowercase error strings).
- Gate for every task: `gofmt -l .` prints nothing, `go vet ./...` and `go test -race ./...` pass.
- Commits: Conventional Commits, subject under 50 chars. Commit only once the user has approved executing this plan. Creating or pushing the GitHub repo `semirm-dev/kwhy` needs the user's explicit go-ahead.

## Review Focus

1. **Values files using YAML anchors/aliases (`&d` / `*d` / `<<:`).** The answer must point at the line where the value text is written (the anchor), not crash or report line 0. Test in Task 2.
2. **`--set` with escaped dots and list indexes** (`a\.b=1`, `list[0].x=2`). The source must read `--set list[0].x=2` and win over files. Test in Task 2.
3. **A chart that fails to render at baseline** (a `required` value missing). Return Helm's message wrapped as `render chart: ...` with exit code 1, no panic and no tracing attempt. Test in Task 6.
4. **Same name in several kinds or namespaces** (Deployment `api` and Service `api`). `deploy/api` must pick the Deployment; a kind matching in two namespaces must ask for `--namespace`. Test in Task 3.
5. **Values ≥1e6 in the baseline render** (`maxBodyBytes: 2000000` renders as `2e+06`). Tracing must still attribute the field (marker run) and the human output must show the baseline value as rendered. Test in Task 4.

### Things to know

- **Errors arrive after tracing.** The CLI runs `Trace` (every marker render) before `SelectDoc` and `ResolvePath`, so a typo in the resource or path costs the full trace before the error. Fix: render the baseline, select and resolve, then trace.
- **Empty leaves are never attributed.** Neither tracing nor the perturbation fallback touches `""`/`0` leaves, so `image.tag: ""` never shows up as a contributor to `image`, though setting it would change the field.
- **`value/value.go` was split by concern** (after Task 6) into `values.go`, `path.go`, `trace.go`, `explain.go`, `report.go`; code only moved. `value_test.go` stays one file.
