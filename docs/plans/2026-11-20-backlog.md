# kwhy backlog: what's missing after v0.5 (2026-11-20)

What each command doesn't cover yet, from the specs (`docs/specs/`), the plans' open decisions and `shortcut:`
comments, and what building v0.5 showed. Sizes: **S** under a day, **M** a few days, **L** a week or more
(spike first). Priority is how often a user hits it.

## `kwhy pod`

| # | Missing | Today | Priority | Size |
|---|---|---|---|---|
| P1 | **Workloads that can't create pods**: ReplicaSet/StatefulSet `FailedCreate` (ResourceQuota exceeded, LimitRange, PodSecurity admission, a webhook denying), Deployment `ProgressDeadlineExceeded` | a workload with no pods gets the template check, which may say "fits" while the real cause is in the ReplicaSet's events: **misleading** | high | M |
| P2 | **Failed Jobs**: `BackoffLimitExceeded`, `DeadlineExceeded` (Job condition `Failed`), pods may already be gone | the Job's pods are diagnosed if they still exist; the Job's own reason isn't shown | high | S |
| P3 | **Pods stuck Terminating**: finalizers, a node that's gone, a volume that won't detach | treated as healthy or skipped (`DeletionTimestamp`) | medium | S |
| P4 | `ds/` targets | refused; pass the pod name instead | medium | S |
| P5 | Preemption: "fits if lower-priority pods X, Y were evicted" | says "doesn't fit" | medium | M |
| P6 | Autoscaler awareness: Cluster Autoscaler / Karpenter adding a node for this pod | not mentioned (cut from v0.4, D3) | medium | S |
| P7 | DRA pods (GPUs via resource claims) | stops with "not supported" | low until GPU users ask | L |
| P8 | Custom scheduler profiles and out-of-tree plugins | default profile, with a warning | low | M |
| P9 | `--chart` render uses the cluster's version for a pod on a node | uses kwhy's default (`v1.37.0`) | low | S |
| P10 | Source link for Kustomize apps | Helm only (depends on V1) | with V1 | — |

## `kwhy value`

| # | Missing | Today | Priority | Size |
|---|---|---|---|---|
| V1 | **Kustomize** (`kwhy value kustomize`): shelved 2026-11-20 after leave-one-out attribution named wrong lines; first attempt on branch `feat/v0.2-kustomize` | Helm only; Kustomize repos get nothing | high | L |
| V2 | **Helm flag parity**: `--set-string`, `--set-json`, `--set-file`, `--set-literal` (also on `change` and `pod --chart`) | unknown flag, so CI pipelines that use them can't reproduce their render | high | S |
| V3 | **Speed**: every run traces the whole chart again (kube-prometheus-stack ~21s); cache the trace index by chart + values hash | no cache; p95 goal of 2s not met on large charts | medium | M |
| V4 | Empty and boolean leaves feeding a field that already has a marker hit (`image.sha: ""`) | not named as contributors | low | M |
| V5 | Group masking: a leaf cancelled by another in the same bisection group (postgresql loses one hit) | recall 0.98–1.00 | low | M |
| V6 | `lookup` in templates | returns empty, as `helm template` does | won't fix offline | — |

## `kwhy change`

| # | Missing | Today | Priority | Size |
|---|---|---|---|---|
| C1 | **Plain manifests** (a directory of YAML, no chart): common in GitOps repos | `--chart` is required | high | S–M |
| C2 | **Kustomize** overlays | not supported (V1's engine would serve both) | high | L |
| C3 | **Several charts per run** / `.kwhy.yaml` (dropped until needed) | one chart per run; monorepos need one Action step per chart | medium | M |
| C4 | Argo CD `Application` / Flux `HelmRelease` discovery (values from the app spec) | values must be passed by hand | medium | M |
| C5 | Rule: **Service selector no longer matches its pods** after the change (traffic goes nowhere), checkable offline | not detected | medium | S |
| C6 | Rule (with `--context`): rollout surge exceeding a `ResourceQuota`, so new pods can't be created | not detected | low | S |
| C7 | Live diff (server-side defaults, drift) | rendered↔rendered only, on purpose | low | M |
| C8 | GitHub Action on macOS/Windows runners (`shortcut:` in `action.yml`) | Linux runners only | low | S |

## Suggested order

1. **v0.6, `pod` completeness:** P1, P2, P3, P4 (all S–M, and P1 removes a misleading answer).
2. **v0.7, `change` and `value` reach:** V2 (S), C1 (S–M), C5 (S), then V3.
3. **v0.8, Kustomize** for `value` and `change` together (V1 + C2 + P10), after a fresh spike.
4. Anytime: D1 and D2 when you want users, D3 when agents are the audience.
