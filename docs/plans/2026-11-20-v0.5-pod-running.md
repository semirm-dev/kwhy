# kwhy v0.5 (`kwhy pod`: why is it not running?) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `kwhy pod` answers "why is this pod not running?" for every common case, not only Pending: image pull errors, crash loops, OOM kills, failing probes, missing config and mounts, evictions. Each problem names the container, the evidence kubelet reported, and, with `--chart`, the values line behind the field involved ("killed at limit 512Mi ← `resources.limits.memory` (values.yaml:9)").

**Architecture:** `pod/` gains `Diagnose`: it reads the pod's status (container and init container states, last terminated state, restarts, conditions) and its recent events, and returns `Problem`s. Scheduling stays as it is: an unscheduled pod gets the v0.4 matrix, a pod on a node gets its problems. Each problem names the pod spec fields it involves, so the v0.4.1 source link works unchanged once it accepts problems as well as checks. `cmd/kwhy` stays wiring only.

**Tech Stack:** Go 1.27.1, `k8s.io/client-go` v0.37.2 (pods, events, logs; no new dependency), kind v0.33.0 for the suite.

**Spec:** `docs/specs/03-pod.md` (section "v0.5: not running"), `docs/plans/2026-11-20-v0.4-pod.md` (v0.4 decisions this builds on).

## Global Constraints

- Read-only: `get`/`list` on pods, events, replicasets and workloads; `get` on `pods/log` only with `--logs`.
- Report what kubelet reported. kwhy names the reason, exit code, limit or message it read; it never guesses why an app exits (exit code 1 is "exited with code 1", nothing more).
- No fixes suggested, as in v0.4.
- JSON stays `kwhy.pod/v1`; new fields are additive (`problems`).
- Follow the `go-guidelines` skill. Gate for every task: `gofmt -l .` prints nothing, `go vet ./...` and `go test -race ./...` pass.
- Commits: Conventional Commits, subject under 50 chars, only once the user approved executing this plan. Tags and releases need the user's go-ahead.

## Problems covered

| Problem | Evidence (pod status, events) | Fields for `--chart` |
|---|---|---|
| `pull` | waiting `ErrImagePull`, `ImagePullBackOff`, `InvalidImageName`; event `Failed` message | `containers[i].image` |
| `crash` | waiting `CrashLoopBackOff` or last terminated `Error`; exit code, restarts, finished at | `containers[i].command`, `args`, `image` |
| `oom` | last terminated `OOMKilled` | `containers[i].resources.limits.memory` (or the request when no limit) |
| `config` | waiting `CreateContainerConfigError`, `CreateContainerError`; message names the Secret/ConfigMap/key | `containers[i].env`, `envFrom` |
| `mount` | events `FailedMount`, `FailedAttachVolume` while `ContainerCreating` | `volumes` |
| `probe` | Ready=False with events `Unhealthy` (readiness, liveness, startup) | `containers[i].readinessProbe`, `livenessProbe`, `startupProbe` |
| `init` | any of the above on an init container (`Init:CrashLoopBackOff` …) | the init container's fields |
| `evicted` | phase `Failed`, reason `Evicted`, message | `containers[i].resources` |
| `sandbox` | event `FailedCreatePodSandBox` (CNI, runtime) | none: node problem |

Anything else not running or not ready is reported as `other` with kubelet's reason and message, never dropped.

## Review Focus

1. **Events expire** (default TTL 1h) and are capped. A crash loop older than that has no events; the diagnosis must still come from the pod status alone. Test in Task 2 (status-only fixtures).
2. **Several containers, several problems.** A sidecar can be fine while the app crashes; init containers fail before app containers start. Every failing container gets its row, init first. Test in Task 2.
3. **Restarted but now fine.** A container with restarts that is running and ready is not a problem; its last OOM kill is shown as a note, not a failure. Test in Task 2.
4. **Logs are user data.** `--logs` is opt-in, prints at most N lines of the previous container instance, and never lands in `-o markdown` (PR comments) unless `--logs` is given. Test in Task 6.
5. **Workload picks the worst pod.** `deploy/x` picks an unscheduled pod first, then the not-ready pod with the most restarts, and says "all N pods ready" when there is nothing wrong. Test in Task 1.

### Task 2: Diagnose a pod on a node

**Files:** Create `pod/diagnose.go`, `pod/diagnose_test.go`.

**Interfaces:**
```go
type Problem struct {
    Container string   `json:"container"`
    Init      bool     `json:"init,omitempty"`
    Kind      string   `json:"kind"`     // pull, crash, oom, config, mount, probe, evicted, sandbox, other
    Reason    string   `json:"reason"`   // kubelet's, e.g. CrashLoopBackOff
    Detail    string   `json:"detail"`   // e.g. "exit 1, 14 restarts, last 2m ago"; "killed at limit 512Mi"
    Events    []string `json:"events,omitempty"` // matching Warning event messages, newest first, deduplicated
}
func Diagnose(ctx context.Context, c kubernetes.Interface, p *v1.Pod) ([]Problem, error)
```

- [ ] **Step 1: Tests**, one per row of "Problems covered", built from pod status and fake events, plus Review Focus 1–3.
